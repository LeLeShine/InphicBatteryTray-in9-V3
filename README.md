# InphicBatteryTray（英菲克 IN9 V3 电量托盘）

[**中文**](README.md) | [English](README.en.md)

给英菲克（INPHIC）IN9 V3 无线鼠标加一个**任务栏电量显示**：不用打开原厂软件，鼠标连上后托盘图标直接按电量填充。

> **实测范围**
> 本项目仅在 **英菲克 IN9 V3** 的 2.4G 接收器上做过实机验证：
> `VID_249A & PID_5C2F`，接口 `MI_02`，输入/输出报告各 33 字节，无 Feature 报告。
> 仓库中保留的 IN10（`1D57` / `045E`）和旧版 IN9（`248A`，Feature Report `0x0C`）分支来自上游项目，**没有**参与本仓库的实机测试，仅作兼容性保留。

## 为什么做这个

原厂配置工具只在它自己的界面里显示电量，必须打开软件、点进设备页才看得到；关掉软件就完全不知道还剩多少电。

Windows 自带的“蓝牙设备电量”对 2.4G 接收器无效，所以只能自己做一个。

| 特性 | 说明 |
|------|------|
| 电量图标 | 鼠标轮廓按电量从下往上填充，青绿（>40%）/ 黄（16–40%）/ 红（≤15%） |
| 充电状态 | 详情里显示“正常（未充电）/ 充电中” |

| 开机自启 | 注册表启动项，菜单里可开关 |
| 主动查询 | IN9 V3 用 33 字节输出报告查询 `0x10` 设备信息 |
| 兼容旧协议 | 保留 IN10 被动推送、旧版 IN9 Feature Report 查询 |
| 零依赖 | 单文件 exe，不需要 .NET SDK，也不需要安装运行时（用系统自带 .NET Framework） |

## 快速开始

1. 获取 `InphicBatteryTray.exe`（直接使用仓库里的构建产物，或按[编译](#编译)自行生成）
2. 放到一个固定目录（例如 `%LOCALAPPDATA%\InphicBatteryTray\`）
3. 双击运行，托盘出现鼠标图标
4. 右键图标 → 勾选「开机自动启动」

> 不建议放在原厂软件目录里——卸载或重装原厂软件时可能被一起删掉。

## IN9 V3 协议（实测）

V3 接收器和旧版 IN9 完全不同：**没有 Feature 报告**，主机必须通过 33 字节的输出报告主动查询，再从输入报告读回复。

### 传输

| 项目 | 值 |
|---|---|
| 设备 | `249A:5C2F`，`MI_02`，产品名 `Wireless-Receiver` |
| 报告长度 | 输入 33 / 输出 33 / Feature 0 |
| 打开方式 | `CreateFileW` + `FILE_FLAG_OVERLAPPED`，共享读写，可与原厂软件同时打开 |
| 查询周期 | 2.5 秒 |
| 读取超时 | 每帧 300 ms，单轮最多读 8 帧 |

### 查询帧（33 字节输出报告）

```
00 10 00 00 ... 00
│  └─ 查询 ID：0x10 = 设备信息（含电量）
└──── Report ID：0x00
```

- **一次只能发一条**：连续发送会收到 NACK `00 <id> 02 FF`，所以每轮只发一条、等回复后再发下一条。
- 实测响应约 2 ms。

### 回复帧

```
00 10 00 01 0B 4D 39 31 30 84 01 31 01 01 64 01 ... 04
│  │  │  │  └ len=11    └──────── payload ────────┘  └ 校验和
│  │  │  └ mode = 0x01（回复）
│  │  └ 状态 = 0x00
│  └ 查询 ID 回显
└──── Report ID
```

| 位置 | 含义 |
|---|---|
| `resp[1]` | 查询 ID 回显 |
| `resp[2]` | `0x00` 正常；`0x02` + `resp[3]=0xFF` 为 NACK |
| `resp[3]` | `0x01` = 回复 |
| `resp[4]` | payload 长度 |
| `resp[5..]` | payload |
| 最后 1 字节 | **校验和 = payload 各字节之和的低 8 位** |

`0x10` 的 payload（11 字节）实测布局：

| payload 下标 | 绝对偏移 | 含义 |
|---|---|---|
| `[0..3]` | 5–8 | 型号 ID，如 `4D 39 31 30` → `"M910"` |
| `[8]` | 13 | **充电标志**：`0` 未充电，`1` 充电中 |
| `[9]` | 14 | **电量**：0–100，整数百分比 |

### 主动推送

鼠标插拔充电线、接收器重连时会主动发一帧（33 字节）：

```
00 C0 <a> <电量> <充电标志> 00 ...
```

- `<a>` **不是**充电状态（未充电时也可能为 1），不要用它判断充电。
- `resp[3]` 是电量（0–100），`resp[4]` 是充电标志（0 未充电 / 1 充电中）。

### 充电时电量固定为 100% 的处理

实测固件在充电期间把电量**固定上报为 `0x64`（100%）**——无论是 `0x10` 回复还是 `0xC0` 推送。如果直接显示，就会出现“明明不到 100%，一插线就变成 100%”。

本工具的处理：

1. 从 `0x10` 回复的 `payload[8]` 或推送的 `resp[4]` 判断是否在充电；
2. 充电期间若电量上报 100%，显示**插线前最后一次真实电量**；
3. 把最后真实电量缓存到 `%LOCALAPPDATA%\InphicBatteryTray\last_battery.txt`，这样程序在充电过程中启动也能恢复该值；
4. 拔线后设备恢复真实上报，显示随之更新。

> 局限：充电期间设备不提供真实电量，如果鼠标是在电量 100% 时插线，显示 100% 是正确的；若缓存值较旧，充电期间显示的是上次记录值。

### 旧版协议（未在本仓库验证）

- **IN10**：设备每约 2 秒主动推送 5 字节 Input Report（Report ID `0x03`，`0x40` 子命令，第 5 字节为电量）。
- **旧版 IN9**：33 字节 Feature Report（`0x0C`），主机发 `0x20` 查询电量，响应电量在 `buf[0x12]`。

这两条分支的帧格式来自上游项目，本仓库未在对应硬件上复测。V3 接收器没有 Feature 报告，旧版 `0x0C` 查询在 V3 上不可用。

## 编译

只需要 Windows 自带的 .NET Framework 编译器，**不需要安装 SDK**：

```powershell
$csc = "C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe"
& $csc /target:winexe /platform:x64 `
    /win32icon:assets\app.ico `
    /resource:assets\MouseIcon.png,MouseIcon.png `
    /out:InphicBatteryTray.exe `
    /reference:System.dll /reference:System.Windows.Forms.dll /reference:System.Drawing.dll `
    src\InphicBatteryTray.cs src\AssemblyInfo.cs
```

或直接运行：

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

## 隐私与只读性

- ✅ 读取 HID 元数据：VID/PID、产品名、报告长度
- ✅ IN9 V3：发送只读的 `0x10` 设备信息查询，读取电量/充电字节
- ✅ IN10 / 旧版 IN9：被动接收推送，或发送只读电量查询
- ❌ 不读取 `Usage Page 0x0001`（Generic Desktop）接口——那是键盘/鼠标本体，跑的是按键和移动数据
- ❌ 不修改 DPI、灯光、按键映射等任何设备设置
- ❌ 不联网、无遥测
- 📝 唯一写入：`%LOCALAPPDATA%\InphicBatteryTray\last_battery.txt`（本地电量缓存），以及程序目录诊断日志 `tray.log`

## 已知限制

1. **只在英菲克 IN9 V3（`249A:5C2F`）上实测**。其它型号、其它固件版本未验证；协议不同就可能读不到电量。
2. **电量精度 1%**，硬件层面没有小数、电压或健康度。
3. **充电期间无法读到真实电量**：固件固定上报 100%，工具只能显示插线前的记录值（见上文）。
4. **离线靠超时判断**（8 秒）：设备关机时不会发送下线通知，短暂休眠也可能被误判。
5. 16×16 托盘图标下细节有限，这是系统图标尺寸的物理上限。

### 读不到电量？

程序默认在同目录写 `tray.log`（超过 512 KB 重建），记录枚举到的接口、收发的原始字节与解析结果。也可以设置环境变量 `INPHIC_TRAY_LOG` 指定日志路径，或使用 `--log=<path>` 参数。

把日志贴到 issue 里通常就能定位问题。
